This does not validate new ISO, setup, marking or storage writes, a 20-photo sequence, originals, live view or the whole family. ## Implemented functions

### Shooting setup and ISO

- Legacy Sync supplies the full current ShootSetup, existing setups and device choices. Select an existing setup or edit only the requested fields while preserving the rest.
- The complete setup covers ISO, quality, framing, toning, Light, sharpening, input / output ICC, camera type, ICCFlag, filename prefix, shooting folder, ordinary / Nearly Lossless compression, NLCompression, orientation and Color.
- Legacy ISO is written within full ShootSetup. Independent 5.041 server evidence supports separate ISO, Orientation, CameraType, SensorCrop, FileCompression, Prefix and ShootingFolder writes after recognizing Sync.CameraSettings. Old-client auditing is not proof of direct ISO.
- 5.041 SensorCrop accepts device-advertised name-only lists. Independent compression is limited to None / Lossless. Independent Prefix cannot increase the known current UTF-8 byte length and is capped at 23 UTF-16 code units. This is an implementation limit, not a hardware specification. Shooting folders are checked before writing.
- No hardcoded ISO steps. Read again before writing to avoid overwriting newer state, then compare the complete expected configuration, untouched fields and required globals through Sync. Incomplete reads, unclear dialects, unsafe serialization or mismatching read-back are not confirmed success.

### 5.041 image processing and the Back page

- New **Back** bottom-navigation entry groups device-provided current values, choices, camera controls and session actions.
- Edit complete ImageSettings or select existing ActiveImageSettings. These are separate from CameraSettings; ISO is not an ImageSettings field.
- Fields include ImageQuality, Color, Framing, Toning, Light, SharpTable, InputProfile, OutputProfile, ICCFlag, Grain, MoireReduction and Saturation. Fields requiring choices are available only when Sync supplies them. Preserve untouched fields, reread before writing and compare the complete read-back.

These writes have not been verified on user hardware. Device Light presets are not arbitrary Kelvin / tint. A readable ShutterSpeed does not provide mechanical shutter-time, aperture or release control.

### Back marking and metadata preservation

- Back Good / Unmarked is independent of local phone stars.
- Strict Base64 / UTF-8 decoding reads the xmp_tag header. Good / Unmarked changes only the third Leaf Flags character, retaining other characters, namespaces and fields. Never replace original metadata with an empty document.
- Classic 4.701 and shared 5.041 evidence independent marking. Sync shootsetup / camerasettings enables Marking-only; existing XMP is still preserved and updated. Without XMP or a recognized dialect, the standard path refuses.
- Matching replies and read-back establish confirmation; a changed phone star does not. New writes still need physical testing.
- Standard photo marking, notes, gray balance and storage operations require a preview from the current back read in this connection. Connection generation is not persisted, so reconnect, upgrade or process restart requires refreshing before standard writes. Laboratory requests use entered targets without every standard semantic / provenance check.

### Back storage management

Create folders, delete empty folders, rename folders, delete photos, and copy / move internally on the back. Review exact source / destination and confirm before sending. Do not overwrite an existing destination. Read affected directories afterward; errors or unconfirmed results are not disguised as successful local path updates.

Creation means creating a folder, not an arbitrary file. Copy / move stays inside back storage and is not MOS transfer to the phone. Deletion has no promised automatic undo.

### Back image inspection

These controls are implemented, with **physical effects unverified**, and are distinguished from phone-side JPEG processing:

| Extension | Required boundary |
| --- | --- |
| Server zoom / Alarm previews | Original 1 / 2 / 4 / 8 and highlight / shadow / both indicators, returning processed JPEG; manually entered original-image protocol coordinates, with no guessed Compose mapping |
| Gray-balance sample / confirm / restore | Inspect sampled preview and returned Light; separately confirm the current photo or future captures; restore is separate; future captures write complete legacy ShootSetup.Light / 5.041 ImageSettings.Light and read back |
| Coordinate pixel / exposure picking | ImageFunction fstops carries `x;y`, not aperture; display histogramlocation / histogramvalue with RAW / JPEG source unconfirmed |
| Back histograms | Parse and display actual variable bin counts, labelled back-provided; RAW / JPEG source unconfirmed; no fixed 256-bin assumption |
| XMP-preserving parsing | Strict decoding retains unrelated fields; damaged input refuses targeted updates; no arbitrary XML replacement editor |

These extensions are not continuous live view or complete MOS transfer.

Future-capture gray balance accepts only a sample returned by the current back in this connection and still tied to the current photo. This dedicated path may bypass the static illuminant list; CSV delimiters remain rejected, other configuration fields are preserved, and Sync verifies the result. Physical effects remain unverified.

### Clock, default notes and session controls

- Write phone-local time and separately read CurrentTime for comparison; no invented protocol time-zone support.
- Read, write and read back future-capture default Annotation / Copyright, separately from the current photo's notes.
- EnableTakenPicture moved to the laboratory. no has not been proved to stop notifications; the main UI has no unproven pause switch.
- FireWire / CameraBattery requests require powersourceselection=support. They also report Ack only, not a confirmed current physical power source.

Gray-balance confirmation / restore Ack likewise does not establish a measured color effect. Related metadata or previews are requested again for inspection.

## New manual laboratory

Open the full-screen laboratory at the top of **Back**. It includes 16 WiView call templates, firmware research entries and a single raw-header console. Brightness, ResetCounter, PIN, FactorySettings, qformat / recovery, XMP-only / annotation+XMP, ReSyncRequest, gain / UserGain, ManualLens and GetImage FP are available for active testing. Unknown inputs have no defaults; users review targets and requests before confirming. Client constructors, firmware handlers, fields and user hypotheses remain distinct; unresolved semantics are not verified standard functionality.

- One encoded control header up to 60 KiB, no outbound binary attachment; a 1–300 second phone timeout, reply tag, exact file_name and attachment matching.
- `*` observes the first complete frame without proving causality; an empty tag sends only. Original replies, Error, nonzero Ack and timeout are recorded without standard success validation.
- Ordinary post-capture reads / configuration refresh pause. Leaving after sending or cancelling disconnects, without promising to undo writes.
- Per-attachment phone limit 16 / 64 MiB, changed while disconnected and applied on reconnect; `.bin`, length / SHA-256 / first 256-byte hex; up to 30 records and a 256 MiB attachment-cache budget.
- ZIP contains complete redacted headers, non-sensitive header hex, original attachments, transport logs and unmatched frames. Known PIN / annotation / copyright / XMP header fields are masked without changing transmitted bytes; binary attachments are not automatically redacted.

GetFile / LiveView / BootRequest / FactoryGain research entries can create a manual **USER HYPOTHESIS** probe, defaulting to `*`; these are not extracted manufacturer wireless syntax. Internal calibration without a known tag does not generate a command; the raw console still accepts a user-entered single header. There is no automatic fuzzing or blind firmware flashing. See the [laboratory guide](../quick-start.en.md#laboratory-manual-testing).

Complete MOS download, continuous Live View, arbitrary photo renaming and full original-client retransmission recovery remain unimplemented as standard functions; hypothesis probes do not establish them. Mechanical shutter release remains manual. See the [feature gap matrix](../feature-gap-matrix.en.md); the [client audit](../protocol-gap-audit.md) uses a 0.2.0 baseline rather than the final release table. CEVersion is an internal compatibility experiment, not the Android or back firmware version or a missing photographic function.

## Installation, update and verification

The target release APK is `Leaf2Android-0.3.0.apk`, ID `com.leaf2android`, minimum Android 12 / API 31 and compile / target SDK 36. Modern / classic PDA, Chinese / English and system-default language remain available.

In-place updates need the same application ID and release signing key. Debug and release may use different signatures; uninstalling removes private previews, local marks and notes. See [installation](../quick-start.en.md) for commands and signing.

Protocol and API 36 emulator coverage includes actual UI ISO selection, confirmation and complete setup read-back, language switching, Android XMP DOM smoke testing, refused writes, read-back mismatches, unintended resets of untouched fields, ISO notifications not polluting choices, and partial-move detection. The new future-capture gray-balance path and final passing counts follow this version's machine reports; unfinished new counts are not filled in ahead of execution. Synthetic peers / images do not establish physical effects.

Source, reference resources and SHA-256 are listed with the release. Absent attachments are not a completed publication. Python research-tool checks and final signed-APK verification follow this work's completed reports. Final results are in [verification-status.json](../../research/reports/verification-status.json) and [apk-verification.json](../../research/reports/apk-verification.json); only records matching this version and APK hash are release evidence.
