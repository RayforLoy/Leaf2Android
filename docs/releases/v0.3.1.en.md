# Leaf2Android v0.3.1 pre-release notes

[简体中文](v0.3.1.md) · [Project home](../../README.en.md) · [User guide](../quick-start.en.md) · [Feature matrix](../feature-gap-matrix.en.md) · [0.3.0 history](v0.3.0.en.md) · [Release page](https://github.com/RayforLoy/Leaf2Android/releases/tag/v0.3.1)

Date: **2026-11-14**. Version **0.3.1, versionCode 4**. **Status: experimental pre-release.** This release adds transaction isolation, request diagnostics and a separate DP-67 writer for Valeo settings timeouts, plus a larger default preview cache. Code changes and static compatibility evidence exist; **no real-back retest yet establishes that the timeout is fixed**.

## Known hardware feedback

- Earlier user reports confirm Bluetooth connection and photo reading on Valeo 22Wi and Aptus 22, without complete firmware, phone / system, app-version or log records.
- The 2026-11-14 update describes working Valeo photo reads and disconnection when changing settings, without identifying the field. The screenshot's `back response timed out; session disconnected...` shows the app closing after waiting for a reply.
- It does not distinguish absent Ack, parsing / matching, interleaved operations, back processing time or an earlier physical loss. Neither a radio cause nor a specific ISO defect is established.

First-hand historical iPAQ / Valeo drop reports exist, without a same-device WiView 1.0.3 / DP-67 reliability A/B or direct public immediate-ISO-write failure. See the [independent review](../valeo-connection-research.en.md). The user corrected that Aptus II lacks Bluetooth; the early II 5 plan is historical, not a current wireless target.

## Setting transactions, timeout and results

- **Whole-operation queuing:** operationLock spans pre-Sync, set and read-back. Automatic GetImage cannot interleave. This locks phone-side work rather than the back or other clients.
- **Notification Ack bypasses the lock:** asynchronous back notifications can still be acknowledged without waiting for the entire setting operation.
- **Specific request summaries:** timeout errors and new diagnostics name the unanswered tag / attributes without values. Stage records distinguish pre-Sync, write Ack and read-back. Better diagnostics do not establish causality automatically.
- **Failure boundaries retained:** timeout still closes the stream and requires manual reconnect. Writes do not retry automatically, and the original DP-67 12-second, up-to-three-attempt / failure-ReSync strategy is not copied.

Offline testing also exposed background Sync from CameraShootSetupChangeNotification clearing just-completed success or read-back mismatch. Automatic refresh now preserves error / notice; a new manual operation clears the old result. **This corrects overwritten app display / verification results, not a proven real-back disconnection cause.** Final checks follow matching-version machine reports.

## DP-67 compatibility

While disconnected, select Shooting-setup compatibility:

| Option | Rule and scope |
| --- | --- |
| AUTO | Use DP-67 when the Bluetooth name contains Valeo and Sync supplies shootsetup; otherwise retain WiView |
| WIVIEW | Explicit WiView settings; separate CameraSettings / ImageSettings still require actual Sync support |
| DP67 | Explicit DP-67 path for renamed backs and other manual selection, still requiring complete core settings and device choices |

This changes serialization, not pairing, SPP services or CEVersion, and is not universal hardware detection.

### Smaller field set and preservation

The 12 core fields follow the original constructor order:

```text
SetupName,ShootingFolder,ISO,ImageQuality,Framing,Toning,Light,
SharpTable,InputProfile,OutputProfile,CameraType,ICCFlag
```

Append Prefix only when already provided in the current setup, without inventing empty fields. Use device choices and retain untouched current values. Incomplete configurations, changed state or unsafe serialization refuse writing.

DP-67 omits WiView FileCompression / NLCompression, Orientation and Color, including top-level orientation / color additions. The standard shooting panel hides those fields. Explicit laboratory probes remain available without establishing support. DP-67 control refresh sends Sync + CurrentTime only, avoiding extra automatic getters.

### `.1` modified slots and preset selection

Editing an original preset clones to `original-name.1`. The original contains(`.1`) rule retains names already carrying that marker. Confirmation identifies the destination and discloses an existing same-name slot update. This is not a backup or automatic undo.

Fresh state is checked first. Read-back verifies expected values, new active, visible untouched fields / globals and unchanged original preset. Selecting originals sends DefaultShootSetup only; selecting modified setups sends complete DP-67 CSV. The original saver, clone and wrapper have [independent static evidence](../dp67-analysis.en.md), supporting this compatibility branch without proving the timeout's cause.

## Preview-cache upgrade

Default preview cache is now **1024 MiB**, with 64 / 256 / 1024 choices. First upgrade migrates an old stored 256 value to 1024 while retaining 64. This runs once; later user choices such as 256 survive restart without another reset.

Caches remain received JPEG previews, without higher back resolution or MOS-original reading. Laboratory per-attachment limits and the separate 256 MiB attachment-cache budget retain their previous rules.

## Installation and inherited functionality

Target APK: `Leaf2Android-0.3.1.apk`; app ID `com.leaf2android`; minimum Android 12 / API 31; compile / target API 36. Source archive: `Leaf2Android-0.3.1-source.zip`; debug APK: `Leaf2Android-0.3.1-debug.apk`. Actual assets and SHA-256 follow the release page.

In-place updates require the same app ID and release signing key. Uninstalling removes private previews, local stars and notes. Build / signing instructions remain in the [user guide](../quick-start.en.md), with private keys outside the repository.

Both languages, both styles, existing image tools and the laboratory remain. Complete MOS, continuous Live View and remote release of this mechanical-shutter setup are not implemented. The 0.3.0 historical notes are not rewritten as this version's test results.
