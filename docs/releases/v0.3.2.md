# Leaf2Android v0.3.2 预发布说明

日期：**2026-11-15**。版本 **0.3.2，versionCode 5**。**状态：已发布（预发布版本）。** 本版修正普通拍后通知的多余确认，增加照片页操作入口和有条件点选灰平衡；用户已报告稳定的拍摄配置路径保留。新版自动预览和新增交互仍待真实 Valeo 复测。

## 用户反馈与证据范围

用户续报 v0.3.1 的 Valeo 蓝牙“非常稳定”，ISO、灰平衡等拍摄设置已可用；拍后自动预览仍显示 `^<Error error_code="0x01" />`，连接保持 READY，手动读取新照片正常。此前 Valeo 22Wi、Aptus 22 的连接 / 读图报告继续保留，见 [设备记录](../implementation-status.md)。

这不是维护者独立复测，也没有补齐固件、兼容模式、完整手机环境或逐张对应记录。不能将部分拍摄设置成功推广为全部字段、Aptus 22 参数操作、20 张连拍、点选取样、当前照片灰平衡或存储操作已通过。用户聊天截图与个人内容不收录到公开仓库；公开参考图只使用模拟器 / 合成图。

## 拍后通知与 Error 0x01

对原版 DP-67、WiView 及经典 4.701 / 共享 5.041 固件的 [完整分析](../capture-notifications-analysis.md) 现已确认：

- 普通 PictureTaken / ImageChange 等异步通知路径不自动发送 `^<Ack />`；WiView 对 Stop 有明确的专属确认。
- 被核对固件 PDA 目录未注册普通 Ack；未知命令处理会走 enum 12 并返回 Error `0x01`。**不能把 0x01 叫 busy。**
- 分包数据的 Ack / Nak 是另一机制，当前应用仍未启用，不能拿它证明普通通知也要 Ack。

旧版额外发出的 Ack 可能先引起 Error，再被正在等待的 GetImage 接收。这能解释用户所述现象，**但没有用户无线抓包证明本次就是该顺序**。静态证据归档在 [capture-notifications](../../reference/dp67/analysis/capture-notifications/)。

0.3.2 已从普通会话和实验室自动处理移除这些额外 Ack，只保留 Stop 专属确认。没有引入盲重试、额外 parametersReady 硬门控或新的拍摄配置写法。完整 Error 拒绝与超时分开：拒绝本身不强制断开仍可用的连接；超时仍关闭会话，手动重连后先读实际状态。新版自动取图是否恢复仍待用户复测。

## 错误码与拒绝诊断

`WireNumbers.errorCode` 严格解析 unsigned DWORD 范围内的十进制、`0x` / `0X` 十六进制：`0x00` 为零，`0x01` 为一，`0xffffffff` 合法；负数、空值、超范围和未知字符保持未知，不能当成成功。

指令拒绝异常保留原请求 / 回复供内部定位，用户错误首部只列请求 tag 和属性名，不列请求值。回复头经已知敏感字段脱敏，PIN、备注、版权、XMP 不直接进入错误文字。它仍属于协议 / I/O 错误；收到 Error 不等于已证明蓝牙物理断线，也不意味着可盲目重发写入。

## 照片页的后背操作

照片主界面新增“后背图像工具”和“照片操作”：前者直达处理预览、灰平衡、像素拾取和后背直方图；后者复用后背标记、后背备注、复制 / 移动和删除。本机星标 / 本机备注保持独立，目录新建 / 删除 / 改名仍在后背页。

删除须二次确认实际设备与完整照片路径。只有目录回读证实已删除，才从手机源列表和对应缓存移除；删除当前项时，有邻片则选邻片。请求拒绝或核对失败保留本地记录，便于重新核实。

移动须核对源消失、目标存在后再清源记录 / 缓存并读取目标；复制保留源，均不覆盖已有目标。失败不证明后背完全未执行，继续前先回读实际目录。没有新增任意单张 MOS 改名，也不把内部复制 / 移动称为向手机下载原片；这些存储效果仍待设备测试。

## 点选白 / 灰区取样

先显式进入灰平衡点选模式，再在当前主预览点希望中性的白 / 灰区域。双指与双击继续缩放，留白及图像外点不会发送请求。

自动点选必须同时具有当前照片元数据的明确方向、`Sync.PictureDimensions`、当前预览 SHA 绑定及同比例证据：

| 条件 | 使用的后背参考网格 |
| --- | --- |
| Landscape | 参考尺寸 max×min |
| Portrait CW / Portrait CCW | 参考尺寸 min×max |
| Auto、未知方向、缺信息或矛盾尺寸 | 不发送自动点选请求，保留手输坐标 |

实际 JPEG 直接显示，不再套用旧 PDA 为临时旋转预览使用的额外旋转。反变换考虑当前 fit、缩放与平移；网格坐标不能冒充 MOS / RAW 传感器像素，也不证明所有固件裁切关系已实测。

App 请求后背返回取样预览和 Light；不从手机 JPEG 编造 Kelvin / tint。返回后可分别确认写入当前照片或用于后续拍摄，未确认不写。后续配置仍完整保留其他字段并 Sync 回读。

每次刷新预览会清旧元数据和采样；取样点、Light、SHA、照片及本次连接必须匹配。重连、换图或同名覆盖不能复用旧点。点选、当前照片提交与真实颜色效果仍需硬件验收，不因用户报告 v0.3.1 拍摄灰平衡可用而自动升级为已验证。

## 验证与交付

本轮验证范围包括通知不额外 Ack、Stop 确认、错误码与脱敏、拒绝后手动读图、点选坐标与来源失效、照片操作及既有设置回读。实际执行项、计数和构建结果以同版本 [verification-status.json](../../research/reports/verification-status.json)、[apk-verification.json](../../research/reports/apk-verification.json) 与关联报告为准，不引用旧 APK 的通过数。合成后背、应用单元测试与 API 36 模拟器均不能替代真实 Valeo 蓝牙连拍。

本版通过 **168 项测试**：25 项 Python、87 项协议 JVM、15 项应用 JVM、41 项 API 36 instrumentation；其中合成对端连续 20 张核对自动下载、文件名及图像内容。Debug / release lint 无错误，签名与 16 KiB 对齐通过。另有 [签名发布包检查](../../research/reports/release-ui-verification.json)，确认 0.3.1 覆盖升级保留已有设置、新安装默认 1024 MiB，以及中英文／双风格／低高度横屏的离线显示；[截图](../screenshots/README.md) 分别注明构建和证据来源。

真机复测应记录准确设备 / 固件 / 系统 / 兼容模式和请求日志，至少 20 张新图逐一核对名称、内容、顺序及自动显示；另测方向、点选边界、刷新失效、当前 / 后续拍摄确认和可删除测试照片。只有实际取得的结果才更新设备支持表。

发布包为签名的 `Leaf2Android-0.3.2.apk`，另提供源码、参考资源和 SHA-256；debug APK 可按构建说明生成。应用 ID `com.leaf2android`，最低 Android 12 / API 31，编译 / 目标 API 36；相同发布签名可覆盖更新，私钥保留在仓库外。构建与安装见 [使用说明](../quick-start.md)。

默认 1024 MiB 预览缓存、一次性升级规则、双风格、跟随系统的中英文与实验室保留。完整 MOS、连续实时取景和当前机械快门遥控仍未实现。0.3.1 及更早的历史发布说明不改写为本轮结果；旧工作区自动附加文件保留且不发布个人内容。
