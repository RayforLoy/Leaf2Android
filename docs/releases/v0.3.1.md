日期：**2026-11-14**。版本 **0.3.1，versionCode 4**。**状态：实验性预发布。** 本版为 Valeo 设置超时增加事务隔离、请求诊断与独立 DP-67 写入路径，并扩大默认预览缓存。代码修改与静态兼容证据已具备，**尚无真实后背复测证明超时已解决**。

## 已知设备反馈

- 既有用户报告：Valeo 22Wi、Aptus 22 可蓝牙连接和读取照片；没有完整固件、手机 / 系统、应用版本或日志。
- 2026-11-14 进一步反馈：Valeo 读图正常，修改设置时才断开，尚未说明实际改了哪项。截图中的 `back response timed out; session disconnected...` 表明 App 等待应答超时后主动关闭会话。
- 截图不能区分缺 Ack、回复解析 / 匹配、事务互插、后背处理时间或较早物理失联；不能据此认定蓝牙硬件原因或特定 ISO 缺陷。

网上有第一手 iPAQ / Valeo 一般掉线经验，但未找到 WiView 1.0.3 与 DP-67 的同机 A/B 稳定性结论，也未找到“写 ISO 立即断线”的公开直接证实。见 [独立网络研究](../valeo-connection-research.md)。用户已纠正 Aptus II 本身无蓝牙，早期 II 5 计划仅作历史，不是当前无线目标。

## 设置事务、超时与结果提示

- **完整操作排队：** operationLock 覆盖预 Sync、设置和回读；自动 GetImage 不再插入这些步骤之间。它是手机端互斥，不承诺锁住后背或其他客户端。
- **通知 Ack 不取此锁：** 后背异步通知仍可及时获得确认，不因等完整设置操作而被阻塞。
- **具体请求摘要：** 超时错误和新增诊断指出未获回复的 tag / 属性名，不含属性值；阶段记录帮助区分预同步、设置 Ack 与回读等待。它们提高可诊断性，不自动推定故障原因。
- **保留失败边界：** 超时仍关闭流并要求手动重连，不自动重试写入，也不照搬原 DP-67 的 12 秒×最多 3 次尝试／失败后 ReSync 策略。

离线测试另捕获一个 App 问题：CameraShootSetupChangeNotification 触发的后台 Sync 会清除刚完成的成功提示或回读不一致错误。现自动刷新保留 error / notice，只有新的手动操作才清除旧结果。**这是显示／验证结果被覆盖的修正，不是已证实的真实后背断线根因。** 最终测试结果以同版本机器报告为准。

## DP-67 兼容模式

断开时在设置选择“拍摄配置兼容模式”：

| 选项 | 选择规则与范围 |
| --- | --- |
| AUTO | 蓝牙名称含 Valeo 且 Sync 下发 shootsetup 时启用 DP-67；否则保留 WiView |
| WIVIEW | 显式保留 WiView 拍摄配置；独立 CameraSettings / ImageSettings 仍须 Sync 实际支持 |
| DP67 | 显式启用 DP-67；可用于改名的后背，仍要求完整核心配置与设备允许值 |

此选择改变写入格式，不更改配对、SPP 服务或 CEVersion，也不是全型号硬件检测。

### 较小字段集与保留规则

DP-67 的 12 核心字段按原构造顺序为：

```text
SetupName,ShootingFolder,ISO,ImageQuality,Framing,Toning,Light,
SharpTable,InputProfile,OutputProfile,CameraType,ICCFlag
```

当前配置已提供 Prefix 时才附加它；缺失字段不补空值。采用后背允许项、保留未编辑现值；配置不完整、状态已改变或无法安全序列化时拒写。

DP-67 不附 WiView 的 FileCompression / NLCompression、Orientation、Color，也不追加全局方向 / 色彩属性；标准拍摄面板隐藏这些字段。实验室仍允许用户明确手动探测，不视为已经确认可用。DP-67 控制页刷新仅 Sync + CurrentTime，避免自动追加未知 getter。

### `.1` 修改槽与选择预设

编辑原预设时克隆到 `原名.1`；沿用原 DP-67 的 contains(`.1`) 判定，已有该标记的名字保留当前修改槽。确认框显示目标槽位，并提示同名槽位已存在时将更新它。它不是备份或自动撤销。

写前刷新，写后核对目标值、新 active、可见未改字段／全局值及原预设保持。选择普通预设只发 DefaultShootSetup；选择已有修改配置则发完整 DP-67 CSV。原包的保存器、clone 与包装器已有 [独立静态分析](../dp67-analysis.md)，这支持实现兼容分支，**不证明差异就是当前超时根因**。

## 预览缓存升级

默认预览缓存改为 **1024 MiB**，可选 64 / 256 / 1024 MiB。旧存储值 256 首次升级会迁至 1024，原有 64 保留；迁移只执行一次。之后用户改回 256 或其他值，重启不会再次重置。

缓存仍是收到的 JPEG 预览，不改变后背分辨率，也不实现 MOS 原片读取。实验室的单附件限额和 256 MiB 附件缓存预算独立，保持原规则。

## 参考包与验证

DP-67 资料收录原始 [Setup.exe](../../reference/dp67/original/LeafDP67-1.2.1-Setup.exe)、[内嵌 CAB](../../reference/dp67/original/LeafDP67-1.2.1.CAB)、解包与静态证据。含私人 PBF 的完整 ZIP 不收录；原厂安装器未被执行，静态读取不是设备验证。

本轮 Python、协议与 API 36 Android 检查均已通过，构建和 APK 签名核验见 [verification-status.json](../../research/reports/verification-status.json) 与 [apk-verification.json](../../research/reports/apk-verification.json)。签名覆盖升级、缓存迁移及显式 DP67 跨重启 / 语言检查也已通过，见 [cache-upgrade-verification.json](../../research/reports/cache-upgrade-verification.json)。测试产物、版本和 APK 哈希以这些最终记录为准；合成后背／模拟器不能替代真实 Valeo 写入。

实机复测需记录模式、准确固件与改动字段、原配置、目标 `.1` 槽和完整请求阶段；确认无自动取图互插、新 active 和原预设保持。若超时，先重连并回读实际状态，再决定后续操作；超时不证明写入从未发生。

## 安装与继承功能

目标安装包为 `Leaf2Android-0.3.1.apk`，应用 ID `com.leaf2android`，最低 Android 12 / API 31，编译和目标 API 36。源码包为 `Leaf2Android-0.3.1-source.zip`，调试包为 `Leaf2Android-0.3.1-debug.apk`；实际附件和 SHA-256 以发布页为准。

同应用 ID 和相同发布签名才能覆盖更新；卸载会删除私有缓存、本机标记与备注。构建和签名方式见 [使用说明](../quick-start.md)，私钥仍留在仓库外。

双语言、双风格、标准图像操作与实验室保留。完整 MOS、连续 Live View 和当前技术相机机械快门遥控未实现；0.3.0 历史发布说明不改写成本版测试结果。
