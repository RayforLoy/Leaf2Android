# Leaf2Android v0.3.0 预发布说明

[English](v0.3.0.en.md) · [项目首页](../../README.md) · [功能状态](../implementation-status.md) · [完整缺口对照](../feature-gap-matrix.md) · [发布页面](https://github.com/RayforLoy/Leaf2Android/releases/tag/v0.3.0)

日期：2026-11-11。**状态：0.3.0 实验性预发布。** 以下功能已接入应用代码，新增功能的硬件效果仍待验证。静态解析、模拟回复和按钮存在均不代替真实后背验收。

## 已收到的硬件回报

用户报告 **Valeo 22Wi、Aptus 22 能正常蓝牙连接并读取照片**。未随报告提供固件版本、实际手机 / 系统、应用版本或日志。该回报不证明本轮 ISO、配置、标记、文件操作已通过，也不证明 20 张连拍、原片、实时取景或整个系列兼容。用户已纠正 Aptus II 本身无蓝牙，不作为当前无线目标；原始 Aptus II 5 计划只作历史记录。5.041 的 PDAInterface 只证明共享固件代码，不证明该系列具备蓝牙硬件。

本轮另复核经典 Aptus **4.701**：含 Aptus 22 模型的共享镜像、9 类 PDA 命令、完整 ShootSetup、独立 Marking 和图像扩展均有独立字节 / 调用链证据，见 [固件蓝牙调查](../firmware-bluetooth-survey.md)。不把它当作 Aptus 22 专用可刷包或用户已安装固件，经典地址也不套用 5.041。

## 已接入功能

### 拍摄配置与 ISO

- legacy Sync 读取当前完整 ShootSetup、已有配置和设备允许值；选择后背已有配置，或只编辑指定字段并保留其余值。
- 完整配置涵盖 ISO、画质、取景框、色调、Light、锐化、输入 / 输出 ICC、机身类型、ICCFlag、文件名前缀、拍摄目录、普通 / Nearly Lossless 压缩、NLCompression、方向和 Color。
- legacy ISO 通过完整 ShootSetup 写入；独立的 5.041 服务端证据支持识别 Sync.CameraSettings 后独立写 ISO、Orientation、CameraType、SensorCrop、FileCompression、Prefix 和 ShootingFolder。不能把旧客户端审计误写成直接 ISO 证据。
- 5.041 SensorCrop 仅接收设备下发的纯名称列表，独立压缩仅 None / Lossless。独立 Prefix 不超过当前已知 UTF-8 字节长度且最多 23 个 UTF-16 代码单元；这是保守实现限制，不是硬件规格。拍摄目录写前检查存在。
- 不硬编码 ISO 档位；写前重新读取，防止旧快照覆盖新状态；写后 Sync 核对整份应写配置、未改字段和必要全局值。读取不完整、方言不明、值无法安全序列化或回读不一致时，不报告确认成功。

### 5.041 图像处理配置与“后背”页

- 新增底栏“后背 / Back”入口，集中显示后背下发的当前值、允许项、相机与会话操作。
- 完整 ImageSettings 编辑与已有 ActiveImageSettings 选择；与 CameraSettings 分离，ISO 不属于 ImageSettings。
- 图像处理字段涵盖 ImageQuality、Color、Framing、Toning、Light、SharpTable、InputProfile、OutputProfile、ICCFlag、Grain、MoireReduction 和 Saturation。需允许值的字段仅在 Sync 下发选项时开放；保留未改字段，写前重读、写后全量核对。

这些新增写入还没有用户硬件验证。Light 的设备预设不等于任意 Kelvin / tint；读取 ShutterSpeed 不等于支持机械快门时间、光圈或释放控制。

### 后背标记与元数据保留

- Good / Unmarked 是后背操作，与手机本地星标独立。
- 对 xmp_tag 头属性执行严格 Base64 / UTF-8 XMP 解码，Good / Unmarked 只定向更改 Leaf Flags 的第三个字符；保留其他字符、命名空间和字段，不用空 XMP 覆盖原始信息。
- 经典 4.701 与共享 5.041 均证实独立 Marking。Sync 出现 shootsetup / camerasettings 时允许 Marking-only；有 XMP 仍保留后定向更新；无已识别方言且无 XMP 则标准路径拒写。
- 匹配的回复与回读才是确认依据，手机星标改变不是后背写入证据；新增写入仍待实测。
- 标准照片标记、备注、灰平衡及存储操作要求预览来自当前后背且在本次连接中重新读取。连接 generation 不持久化；重连、升级、进程重启后标准写入前须刷新。实验室另按用户输入目标执行，不继承全部标准语义 / 来源检查。

### 后背存储管理

新增目录、删除空目录、目录改名、删除照片、后背内部 copy / move。操作需明确源 / 目标和用户确认，不覆盖已有目标，完成后回读相关目录。错误或未确认结果不伪装成手机映射已更新的成功状态。

这里的“新增”是新建目录，不是创建任意文件；copy / move 是后背内部存储操作，不是向手机下载 MOS 原片。删除也没有可承诺的自动撤销。

### 后背图像检查

以下入口已实现，**硬件效果待验证**，与本机 JPEG 处理分别标识：

| 扩展 | 必须保留的边界 |
| --- | --- |
| 服务端 zoom / Alarm 预览 | 原厂 1 / 2 / 4 / 8 和亮 / 暗 / 两者警示，接收处理 JPEG；手填原图协议坐标，不猜 Compose 到原图的映射 |
| 灰平衡取样、确认、恢复 | 先看取样预览及返回 Light，分别确认写当前照片或用于后续拍摄，另可恢复预览；后续拍摄完整写 legacy ShootSetup.Light / 5.041 ImageSettings.Light 并回读 |
| 坐标像素 / 曝光拾取 | ImageFunction 的 fstops 是 `x;y` 坐标，不是光圈；显示 histogramlocation / histogramvalue，RAW / JPEG 来源未确认 |
| 后背直方图 | 解析和显示实际任意桶数，标注来自后背；RAW / JPEG 来源未确认，不假定固定 256 桶 |
| XMP 保留解析 | 严格解码并保留无关字段；损坏数据拒绝定向更新，不提供任意 XML 覆盖编辑 |

这些扩展也不等同于连续实时取景或完整 MOS 下载。

灰平衡用于后续拍摄只接受本连接当前后背返回、仍关联当前照片的取样值；该专用路径可不受静态光源列表限制，仍拒 CSV 分隔符，保留整份配置的其他字段并 Sync 回读。硬件效果待验证。

### 时间、默认备注与会话控制

- 同步手机本地时间，并单独读取 CurrentTime 核对；不猜测协议时区。
- 后续拍摄默认 Annotation / Copyright 读取、写入、回读，与当前照片备注分开。
- EnableTakenPicture 已移入实验室。尚未证明 no 停止通知，主界面不提供未经证实的暂停开关。
- FireWire / CameraBattery 请求仅在 powersourceselection=support 时开放；也仅显示 Ack，不冒充已确认当前供电来源。

灰平衡确认 / 恢复的 Ack 亦不能代替真实颜色效果验证；会重新请求相关元数据或预览供检查。

## 新增手动实验室

“后背 / Back”页顶部打开全屏实验室，包含 16 个 WiView 调用模板、固件研究条目和单原始控制头控制台。Brightness、ResetCounter、PIN、FactorySettings、qformat / recovery、XMP-only / annotation+XMP、ReSyncRequest、增益 / UserGain、ManualLens、GetImage FP 等可主动验证；未知输入不默认取值，展示目标和请求后由用户确认发送。客户端构造、固件处理链、仅字段和用户假设分别标识，未知语义不当作标准功能已验证。

- 单控制头编码后最多 60 KiB，无出站二进制附件；手机端超时 1–300 秒，可设回应标签、精确 file_name 和附件匹配。
- `*` 只观察首个完整帧，不证明请求因果；空标签只发送。原始回复、Error、非零 Ack 和超时分别记录，不使用标准成功判断。
- 实验期间暂停普通拍后读图 / 配置刷新；已发实验后退出或取消会断开，不能据此承诺撤销写入。
- 单附件手机限额 16 / 64 MiB，断开时改、重连生效；收到 `.bin`、长度 / SHA-256 / 前 256 B hex，最多 30 条记录、256 MiB 附件缓存预算。
- ZIP 导出含完整脱敏头、非敏感 header hex、原始附件、transport 日志和未匹配帧。已知 PIN / 备注 / 版权 / XMP 头字段默认 mask，发送字节不变；二进制附件不自动脱敏。

GetFile / LiveView / BootRequest / FactoryGain 研究条目可手动“建立假设探测”，生成标为 **USER HYPOTHESIS** 的候选头并默认 `*` 观察；它们不是提取到的厂商无线语法。无已知 tag 的内部校准不自动造指令，原始控制台仍允许用户填写单头。不做自动 fuzz 或盲刷固件。详细步骤见 [实验室指南](../quick-start.md#实验室手动验证)。

MOS 原片下载、连续 Live View、任意照片改名和完整原厂重传恢复仍未作为标准功能实现；假设探测不等于扩展已经成立。当前技术相机机械快门继续手动释放。逐项范围见 [功能缺口对照](../feature-gap-matrix.md)；原始 [客户端审计](../protocol-gap-audit.md) 的 0.2.0 基线不是本版最终表。CEVersion 仅作为内部兼容实验模板，不冒充安卓或后背固件版本，也不是缺失的摄影功能。

## 安装、更新与验证

目标 release 包为 `Leaf2Android-0.3.0.apk`，应用 ID `com.leaf2android`；最低 Android 12 / API 31，compileSdk / targetSdk 36。保持现代 / 经典 PDA、中英文以及默认跟随系统语言。

只有相同应用 ID 和相同发布签名才能覆盖升级。debug 与 release 签名可能不同；卸载会删除私有缓存、本机标记和备注。签名设置和安装命令见 [安装说明](../quick-start.md)。

本轮协议与 API 36 模拟器测试范围包括真实界面选择 ISO 后确认和完整配置回读、语言切换、Android XMP DOM 冒烟，以及拒写、回读不一致、未改字段意外重置、ISO 通知不污染候选、部分 move 检测。灰平衡用于后续拍摄的新路径与最终通过项数以本轮机器报告为准；不预填未完成的新计数。测试使用合成后背 / 图像，不是新功能的真实硬件验收。

源码、参考资源及 SHA-256 随发布页列出；附件未出现前不宣称已发布。Python 研究工具和最终签名 APK 核验以本轮完成报告为准。最终结果见 [verification-status.json](../../research/reports/verification-status.json) 和 [apk-verification.json](../../research/reports/apk-verification.json)，只有版本和 APK 哈希与本版一致的记录才作为本版结果。
